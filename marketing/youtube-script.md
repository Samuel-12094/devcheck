```
[Plan : toi face caméra]

"Si XAMPP ne démarre plus, ou si MySQL refuse de se connecter,

```

---

### Le problème (0:30 - 1:30)

```
[Plan : écran d'ordinateur, XAMPP Control Panel]

"Voici XAMPP. Vous cliquez sur Start. Et là... rien.

Ou pire : MySQL démarre, mais la connexion échoue.

Vous passez des heures à chercher sur Google.
Vous essayez 10 solutions différentes.
Et vous ne savez toujours pas d'où vient le problème."
```

---

### La solution (1:30 - 3:00)

```
[Plan : interface web DevEnv Doctor]

"DevEnv Doctor. 36 tests automatiques.

Regardez :
- PHP : version 8.2.12, toutes les extensions sont là
- MySQL : connexion OK, CRUD complet validé
- Fichiers : écriture, lecture, suppression
- Outils : Node, Git, Composer, VS Code
- Réseau : ports, DNS, HTTPS

En 10 secondes, vous avez un rapport complet.

Et si quelque chose ne va pas, chaque échec affiche
le fichier, la directive et la ligne à corriger."
```

---

### Démonstration (3:00 - 4:00)

```
[Plan : simulation d'un problème]

"Imaginons que MySQL ne démarre pas.

Le rapport montre :
- Port 3306 : fermé
- Connexion mysqli : échec

Correctif : démarrez MySQL dans XAMPP Control Panel.

Autre exemple : extension PHP manquante.

Le rapport montre :
- Extension 'mysqli' : absente

Correctif : décommentez extension=mysqli dans php.ini"
```

### Conclusion (4:00 - 4:30)

## Vidéo 2 : "Pourquoi j'ai créé DevEnv Doctor"

**Durée :** 5-7 minutes
**Objectif :** Storytelling, connexion émotionnelle

---

### Accroche (0:00 - 0:30)

```
"J'ai passé 3 jours à configurer XAMPP.

3 jours. Pour un outil qui est censé être simple.

Alors j'ai créé quelque chose qui règle le problème."
```

---

### L'histoire (0:30 - 2:30)

```
[Plan : toi face caméra]

"Quand j'ai commencé à apprendre PHP, j'ai installé XAMPP.

Premier problème : le port 80 était pris par Skype.
Deuxième problème : MySQL ne démarrait pas.
Troisième problème : les extensions PHP n'étaient pas chargées.

J'ai passé des heures sur Google.
J'ai essayé 10 solutions différentes.
Et je me suis dit : pourquoi il n'y a pas un outil
qui vérifie tout ça automatiquement ?

Alors j'ai créé DevEnv Doctor."
```

---

### La démonstration (2:30 - 5:00)

```
[Plan : écran d'ordinateur]

"36 tests. 5 catégories.

1. Serveur & PHP
   - Version, extensions, php.ini, sessions

2. Base de données
   - Connexion, CRUD, transactions

3. Fichiers & droits
   - Écriture, lecture, suppression

4. Outils CLI
   - Node, Git, Composer, VS Code

5. Réseau
   - Ports, DNS, HTTPS

Et le meilleur : chaque échec affiche le correctif exact."
```

---

### L'impact (5:00 - 6:00)

```
[Plan : toi face caméra]

"Mon but : faire gagner du temps aux développeurs.

Si vous passez 3 jours à configurer votre environnement,
cet outil est pour vous.

Si vous voulez juste vérifier que tout fonctionne,
cet outil est aussi pour vous.

C'est open source. C'est gratuit. C'est sur GitHub."

---

### Appel à l'action (6:00 - 6:30)

```
"Le lien est dans la description.

Et dites-moi en commentaire : combien de temps
